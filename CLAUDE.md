## About this repository

This repository composes development environments ("slots") on demand with
`./env.sh`. Each slot is a set of **git worktrees**, one per repo, under
`~/.local/share/dev-env/worktrees/<slot>/<repo>`. They're linked into
`slots/<slot>/<category>/` (`clients/`, `servers/`, `libraries/`, ...). Changes
in a slot's worktree only affect that slot. Every worktree in a slot is on the
slot's feature branch, `feature/<name>/feature`.

If you're running inside `slots/<slot>/`, that slot is yours. Its own
`CLAUDE.md` names it and gives its commands. ACTIVE.md above describes every
active slot, including what each one is for.

## Running a slot

Each slot has a tmux session named after it, generated by tmuxinator:
- **A window per repo:** the editor on the left (setting `editor`, nvim by
  default), the run command top right, tests bottom right.
- **A `hosts` window** running `./env.sh hosts <slot> --watch --open`.
- **An `environment` window** with Claude (unless the `claude` setting is off).

Commands, run from the repo root (`env.sh` finds its own location, so a full
path works from anywhere):

| Command | What it does |
|---|---|
| `./env.sh start <slot>` | Runs the slot's apps, hostname watcher and tab group. In a session opened with `--no-start` it fills in the waiting panes; with no session, it starts one. Use this for "start everything". |
| `./env.sh status <slot>` | The slot's repos, branches and hostnames. |
| `./env.sh hosts <slot>` | One-off refresh of the slot's hostnames. The `hosts` window normally keeps them current. |
| `./env.sh open <slot> [--all]` | Opens the slot's apps in the browser (`--all` adds servers): a Chrome tab group titled after the slot (needs the extension in `chrome-extension/`, loaded once by the user), a plain tab each, or nothing, per the `browser` setting. |
| `./env.sh shared [add\|remove\|update\|start]` | Tools kept running outside any slot (e.g. an internal admin console), in a `shared` tmux session. `add` and `remove` are interactive (fzf). |
| `./env.sh kits [apply] <slot>` | Which of the slot's repos have repo kits and which aren't set up to run; `apply` puts newly made kits into the slot's worktrees. |
| `./env.sh ref [add\|remove\|update] <slot> [<repo>...]` | Reference repos: in the slot to read, not change (`slots/<slot>/reference/`, detached at the latest base branch, no window, kit or hostname). With repo names it doesn't prompt, so add the ones the work needs yourself. |
| `./env.sh deactivate <slot>` | Removes the slot's worktrees and hostnames (its `plans/<slot>/` notes are kept). It's destructive, so ask first. |

`activate`, `adhoc`, `save`, `shared add` and `shared remove` prompt
interactively; let the user run those. `./env.sh doctor` shows what's installed
and which settings are in use.

## Hostnames

Running apps are reachable at `http://<repo>.<slot>.localhost`, and shared tools
at `http://<repo>.localhost`, through Caddy (a brew service on port 80).
- `hosts` finds each app's port by matching listening processes to the slot's
  worktrees, so it follows apps that move port.
- Keycloak is `http://keycloak.localhost`, for browsing only. Apps and servers
  must keep using `localhost:<port>`, because Keycloak puts the requested
  hostname into its tokens' issuer.

## Configuration outside this repo

- `~/.config/dev-env/config.yml`: Bitbucket credentials, plus optional settings
  `repo_root`, `editor`, `claude`, `browser`, `base_branches` and
  `skip_repos` (README "Settings"; each also
  has a `DEV_ENV_*` variable that overrides it).
- `~/.config/dev-env/tmux-overrides/<slot>.tsv`: the slot's pane commands,
  extra windows, and `host` pins or extra names (e.g. `host keycloak 8080` in
  `shared.tsv`).
- `~/.config/dev-env/repos/<repo>/`: repo kits, applied to every new worktree
  of that repo:
  - `panes.tsv`: how to run the repo;
  - `files/`: gitignored local config, symlinked into the worktree, or rendered
    from `.tmpl` files with `{{slot}}`, `{{worktree}}` and
    `{{url:<repo>|<default>}}` filled in.

  When a repo needs local setup to run, put it in its kit rather than only in
  one worktree. A slot's `CLAUDE.md` lists its repos that aren't set up yet
  and how to build their kits.
- `~/.config/dev-env/setup-notes.md`: the user's notes on their local services,
  copied into the kit-setup instructions of each slot's `CLAUDE.md`.
- `~/.config/dev-env/caddy/`: generated Caddy sites and the slot app lists the
  Chrome extension reads. Don't edit these by hand.

## Gotchas

- In zsh, `"$var:h"`, `"$var:t"` and similar are path modifiers. Write
  `"${var}:hosts"` when building tmux targets such as `session:window`.
- Servers with fixed ports (see CLAUDE.local.md, if present) can't run in two
  slots at once. UI dev servers move to the next
  free port.
- A slot's Java server windows may show a build pane that has finished. That's
  expected; it's not an app that needs starting.

## Plans

Save plans, findings and other working notes under `plans/<slot>/` in this
repo, with descriptive file names (e.g. `plans/my-feature/login-flow-findings.md`).
Each slot links its folder in as `slots/<slot>/plans`, so from inside a slot
just write to `plans/`. `plans/` is gitignored, and a slot's plans are kept
when it's deactivated. Notes that aren't about one slot go in `plans/general/`.
